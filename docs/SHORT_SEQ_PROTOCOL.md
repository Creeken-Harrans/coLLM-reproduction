# 测试集短序列口径：被静默丢弃的 10 台发动机（REVISIONS #53）

> 状态：**评估口径审计记录**，非方法改动。默认口径（`short_seq="drop"`）下所有既有
> 结果逐位不变；本文档记录一个此前未登记的口径事实、它的结构性影响，以及"补齐后
> 重训"为何不成立。日期：2026-09-28。

## 结论速览

1. **论文只规定"窗口 50 / 步长 1"，未交代周期数不足 50 的测试序列怎么办。** 既有实现
   由 `max(0, n − window + 1)` 静默丢弃：**FD001 丢 7 台、FD003 丢 3 台**，评估样本量
   从 100 台降到 93/97 台。
2. **被丢的恰是健康度最高的发动机。** 丢弃组末端 RUL 均值 **119.0**（FD001）/ **136.3**
   （FD003），保留组仅 **72.2 / 73.4**。原因是 test 序列长度与末端 RUL 强负相关：
   **corr = −0.598（FD001）/ −0.484（FD003）**。
3. **补齐需要前置填充，而模型从未见过填充序列 → 补齐后指标略微变差，不是变好。**
   FD001 CoLLM-A 12.628 → 12.631~13.437；FD003 几乎不动（10.581 → 10.552~10.586）。
4. **结果由填充方式主导，而非模型能力。** 同一批数据换填充方式，FD001 逐周期口径差
   **0.67 RMSE**；单台（unit 14）只差 **4 步**填充，LM 预测就从 **64.1** 跳到 **131.6**。
5. **"重训"对这一改动是严格的 no-op**（已证实，见 §6）——测试集组成不进入梯度、早停或选点。

**因此**：补齐不能作为提升指标或收窄论文差距的手段（曾有此假设，已被证伪）。它的价值
在于暴露上述结构性口径偏差，供读者判断表 II/III 数字的可比性。

## 1. 现象：窗口数对不上账

`x_test` 的窗口数与"总行数 − 49×unit 数"不符：

| 子集 | 测试总行数 | 天真窗口数 | 实际窗口数 | 差额 |
|---|---|---|---|---|
| FD001 | 13096 | 13096 − 4900 = 8196 | **8255** | +59 |
| FD003 | 16596 | 16596 − 4900 = 11696 | **11717** | +21 |

差额来自**周期数 < 50 的 unit**：它们单个窗口都产不出，`max(0, n − 49)` 给出 0，
而天真公式给了负数，于是实际值反而更大。对账成立：

```
FD001: 8196 + Σ(49 − n_i) over 短序列 = 8196 + 59 = 8255  ✓
FD003: 11696 + 21 = 11717                                  ✓
```

（对照：训练集无此问题，FD001 最短 128 周期、FD003 最短 145 周期，全部 ≥ 50。）

被丢弃的发动机（`<50` 周期）：

| 子集 | unit（文件内编号） | 周期数 | 末端 RUL | 保留组末端 RUL 均值 | 丢弃组均值 |
|---|---|---|---|---|---|
| FD001 | 1, 2, 14, 22, 25, 39, 85 | 31, 49, 46, 39, 48, 37, 34 | 112, 98, 107, 111, 145, 142, 118 | 72.2 | **119.0** |
| FD003 | 37, 52, 88 | 47, 38, 41 | 145, 120, 144 | 73.4 | **136.3** |

`data/processed/*_meta.json` 中的 `test_engines` 字段（=100）是**全部 unit 数**，不等于
实际参与评估的发动机数。本次新增 `test_engines_evaluated` / `short_units` /
`dropped_units` / `short_engines` 四个审计字段以消除该歧义。

## 2. 为什么是结构性问题

CMAPSS 的 test 序列长度与末端 RUL 强负相关——**越健康，跑到截断点用的周期越少**：

```
FD001  corr(序列长度, 末端 RUL) = −0.598
FD003  corr(序列长度, 末端 RUL) = −0.484
```

而当前指标按**窗口**加权（每台贡献 `n − 49` 个窗口，FD001 最多 254、最少 0）。两者叠加
的效果是：**测试指标系统性偏向不健康发动机**——一台末端 RUL=10 的发动机贡献 254 个
窗口，一台末端 RUL=145 的贡献 0 个。FD001 中，末端 RUL<50 的发动机占据了 **44.6%** 的
窗口；末端 RUL=125（截断上限）的窗口占 **43.2%**。

这不是实现错误（论文未规定），但它是**未登记的**：`docs/` 全部文档与 52 条 REVISIONS
记录中均无此项。

## 3. 实现

`DataConfig` 新增两个字段，默认值**保持既有行为**：

```python
short_seq: str = "drop"       # 'drop' | 'minpad' | 'percycle'
short_pad: str = "replicate"  # 'zero' | 'replicate'
```

- `minpad`：前置填充至恰好 window → 每台 **1 个**末端窗口（最小填充）
- `percycle`：每个 cycle 一个窗口，末端为 c 的窗口填充 `window − c`（早期 cycle 填充量极大）
- `zero`：填 z-score 后的 0（即训练均值）；`replicate`：重复该 unit 首行

标签与正常窗口同一约定：`RUL_FD00X[unit] + (周期数 − 末端 cycle)`，再按 `rul_cap=125` 截断。

**默认 `drop` 下 `short_x` 为空数组，`te_x`/`te_y` 与改动前逐位一致**（已用 npz 逐键
`np.array_equal` 验证，见 §7）。非默认口径的 `npz`/`meta`/`results` 自动落到带后缀的
文件名，不覆盖论文口径的权威产物。

## 5. 机制：填充是 OOD，不是"零误差样本"

曾假设这 10 台健康发动机补进来会**降低** RMSE（真值贴近 125 上限，模型应预测 ≈125）。
**该假设被实测证伪。** 真实机制是模型对填充输入**外推饱和**，预测普遍落在 118–125，
而 FD001 那 7 台真值分散在 98–118：

```
FD001 逐台（minpad，两列分别是 zero / replicate 填充）
 unit  len  pad  真值 |  zero:  SM      LM      |  rep:  SM      LM
   1    31   19   112 |       118.6  132.4(+20) |       118.5  127.2(+15)
   2    49    1    98 |       118.4  124.0(+26) |       118.4  123.3(+25)
  14    46    4   107 |       104.4   64.1(−43) |       117.4  131.6(+25)
  22    39   11   111 |       118.6  131.6(+21) |       118.6  130.9(+20)
  25    48    2   125 |       118.6  114.8(−10) |       118.6  121.3( −4)
  39    37   13   125 |       118.5  131.6( +7) |       118.5  125.6( +1)
  85    34   16   118 |        84.1  132.4(+14) |        97.3  113.5( −5)
FD003 逐台
  37    47    3   125 |       123.7  124.6( −0) |       123.8  122.2( −3)
  52    38   12   120 |       123.5  126.7( +7) |       123.3  127.2( +7)
  88    41    9   125 |       123.7  125.9( +1) |       123.2  126.5( +2)
```

**对照组（基线测试集按真值分带）证明问题不在"高 RUL 难预测"**：

| 分带 | FD001 n | SM RMSE | LM RMSE | LM 预测均值 | FD003 n | SM RMSE | LM RMSE |
|---|---|---|---|---|---|---|---|
| RUL<50 | 853 | 9.088 | 8.567 | 35.5 | 750 | 5.661 | 6.511 |
| 50≤RUL<100 | 2252 | 17.326 | 19.389 | 87.4 | 2455 | 17.928 | 18.631 |
| 100≤RUL<125 | 1585 | 13.288 | 14.953 | 110.7 | 1698 | 13.313 | 14.179 |
| RUL=125(cap) | 3565 | 10.191 | **9.715** | 120.7 | 6814 | 5.387 | **6.681** |

真值=125 的正常窗口上 LM RMSE 只有 9.7/6.7——模型对高 RUL **原生窗口**并无问题。
FD003 补齐后几乎不动，正因为其 3 台真值（120/125/125）落在模型能预测好的区间（SM 预测
≈123，误差 1~3）；FD001 的 7 台真值分散且偏低，模型却统一预测 ≈118–125，误差 6~26。

**敏感性是决定性证据**：unit 14 只填 4 步，LM 预测从 **64.1** 变到 **131.6**（真值 107）；
unit 85 从 **84.1** 变到 **97.3**。同一台发动机、同一批真实观测，仅因缺失前缀怎么补，
预测摆动几十个 RUL 单位。这说明补齐测出的是**填充选择**，不是模型能力。

## 6. 为什么"重新训练"不能解决

已验证：**测试集组成不进入训练**。

| 位置 | 事实 |
|---|---|
| `scripts/train/train_small.py:45,75-76` | `te_ld` 在 `load_state_dict(best_ckpt)` **之后**才用于 `evaluate` |
| `scripts/train/train_large.py:44,59-60` | 同上 |
| `scripts/train/train_conf.py:82` | `feats["test"]` 仅写入日志 |
| `collm/training.py:88,91` | 早停与选点只看 `val_rmse`（`val_loader`） |

因此改测试集后重训得到的权重**逐位相同**。成本上整条 pipeline 约 15 分钟
（FD001 stage1 1min / stage2 2min / stage3 <1min；FD003 stage1 1min / stage2 6min /
stage3 ~1min），所以"贵"不成立——**"无效"才是**。本次未重训。

（若要让模型真正见过填充序列，须在训练时也做截断+前置填充增强，再重训三阶段。那会
改变模型，使结果与论文口径及第四轮基线不再可比——本次未采用。）

## 7. 复现性与验证

- **默认口径逐位不变**：改动后以 `short_seq="drop"` 重跑，落盘 npz 的 10 个键
  （`x/y_train`、`x/y_val`、`x/y_test`、`*_unit_ids`、`mu`、`sigma`）与改动前
  **`np.array_equal` 全部为 True**（FD001/FD003 均通过）。
- **同会话内原始代码 == 改动后代码**：`git checkout` 还原三份原件后重跑 FD001，
  与改动后结果 `json.dumps(sort_keys=True)` **完全相等**（LM 13.922453880310059、
  CoLLM-A 12.628264427185059）；同代码连跑两次亦逐位相等。
- **跨会话有 ~1e-6 抖动**：与 2026-09-28 17:13 的旧 `FD001_results.json` 相比，
  浮点指标在第 7 位有效数字有差异（LM 13.922523498535156 vs 13.922453880310059），
  而 `flops`、`alpha`、`n_test` 等结构字段完全一致。批量 128/256/512/1024/2048
  均不能复现旧值，故**非** batch 效应；判定为跨进程的 cuBLAS/cuDNN 归约顺序差异
  （未追到确切根因，如实记录）。**量级远低于 3 位小数的报告精度，不影响任何已发布数字。**

## 8. 用法

```bash
# 论文口径（默认，既有结果不变）
python scripts/assess/evaluate.py --subset FD001

# 纳入短序列（写带后缀的 npz/meta/results，不覆盖权威产物）
python scripts/assess/evaluate.py --subset FD001 --short-seq minpad   --short-pad replicate
python scripts/assess/evaluate.py --subset FD001 --short-seq percycle --short-pad zero
```

`evaluate.py` 在丢弃发生时打印告警：

```
[FD001] ⚠️ 测试集丢弃 7 台短序列发动机 [1, 2, 14, 22, 25, 39, 85]（末端 RUL 均值 119.0）
        → 实际评估 93/100 台；详见 docs/SHORT_SEQ_PROTOCOL.md
```

## 9. 建议

- **表 II/III 的数字保持论文口径（drop）**，与论文可比性优先；本记录的作用是让读者
  知道测试集实际覆盖 93/97 台、且缺的是最健康的一批。
- **不要用补齐去"改进"指标**：方向随子集反转、量级由填充方式主导，属测量伪影。
- 若未来要严肃处理短序列，正确做法是**训练侧也做填充增强**（让填充进入分布），
  而非只在评估侧补——那是一次方法改动，须与论文口径分开报告。
